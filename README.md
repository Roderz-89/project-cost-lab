# Project Cost Lab

UK home-project cost range calculator and guides from **Rodway Labs**. Live at [https://projectcostlab.co.uk](https://projectcostlab.co.uk).

**Status (15 Nov 2026):** indexable. `robots.txt` allows crawling and lists the sitemap. HTML pages use `index,follow`. **Ads are off** (`config/ads.json` → `enabled: false`), so `ads.txt` authorises nobody and no ad code is on any page. The first-party consent banner has been removed: the site sets no cookies and stores nothing on the device. Visits are counted with cookieless **Cloudflare Web Analytics** (enable it in the dashboard — see Analytics below).

## What it is

Illustrative 2026 UK cost bands for 57 home projects. Size, spec, region, access, occupation, listed uplift, VAT display, contingency and extras are editable. The mid figure is a **band for planning**, not a quote. The VAT toggle is a display choice, not a ruling. Not a contractor, architect or quantity surveyor.

## Deploy

Cloudflare Worker named `projectcostlab`, **assets only** (no Worker script runs per request), custom domain apex `projectcostlab.co.uk`.

See **Build & checks** below for the exact deploy command.

`wrangler.jsonc` has no `main` and no `run_worker_first`; it uses `workers_dev: false`, `html_handling: auto-trailing-slash` and `not_found_handling: "404-page"`. Internal links use clean paths (no `.html`).

- `_redirects` — generated by `scripts/build-static-config.mjs` (also run by `build-news.mjs`): one single-hop **301** for every non-canonical variant of every page (`/x.html`, `/x/`, `/x/index`, `/x/index.html`, `/index.html` → `/`, `/guides` → `/guides/`, `/news/page/1` → `/news`). Explicit rules win over `html_handling`, which would otherwise answer with 307s.
- `_headers` — generated by the same script: HSTS, nosniff, Referrer-Policy, Permissions-Policy, X-Frame-Options, `Cache-Control: public, max-age=0, must-revalidate`, and a **fixed** CSP whose `script-src` lists a sha256 hash for every inline script/handler (no nonce, no ad domains). If you add or change an inline script, rebuild and run the checks.
- `404.html` — the not-found page (`<meta name="robots" content="noindex">`), served with status 404 for any missing path, including out-of-range `/news/page/N`.
- `www` → apex and `http` → `https` are **not** in the repo: they are a Cloudflare dashboard Single Redirect rule plus Always Use HTTPS (`_redirects` cannot do domain-level redirects).
- Rollback: redeploy commit `70b2cd4` (the last `worker.js` version).

## Build & checks

Plain static HTML; no bundler. Node scripts (Node 18+), not served (listed in `.assetsignore`):

```bash
node scripts/build.mjs        # runs, in order: build-news, build-costs, seo, ads, build-static-config
node scripts/check.mjs        # calculator (57 projects, knobs move the band, 0 NaN), nav/footer, CSP hashes + allowed hosts,
                              # JSON-LD, internal links, pages match config/ads.json, ads.txt, Open Graph tags,
                              # /costs pages (preloaded, in sitemap, linked, figures equal calc()), news pages in sync,
                              # _redirects/_headers up to date, single-hop 301s, 404.html noindex
python3 scripts/og-images.py  # share images in /og (Pillow + Inter font); rerun after adding a cost page
```

- `scripts/build-costs.mjs` — `/costs/<slug>` pages from `content/costs.json` (written copy) + the calculator. Every £ figure is computed from `calc()` at build time; the build fails if the written copy contains £ amounts. Also writes the static `/projects` catalogue rows (crawlable links), `COST_PAGES` in `js/data.js`, the home page "Popular cost pages" links and the `/costs` sitemap entries. Add a page only with its own intro, drivers, permissions note and FAQs.
- `scripts/seo.mjs` — Open Graph/Twitter tags on every page (between `<!-- og -->` markers) and a BreadcrumbList on guides.
- `scripts/ads.mjs` — the ad switch (see Ads below).

**Auto-deploy (from 15 Nov 2026):** the `projectcostlab` Worker is connected to this repo with Cloudflare Workers Builds. Every push to `main` runs `node scripts/check.mjs` (build fails if any check fails) then `npx wrangler deploy`. Generated files are committed, so run `node scripts/build.mjs` locally before pushing. Other branches get preview builds.

Manual fallback — run both scripts, then deploy (token is read from the box secret, never printed):

```bash
CLOUDFLARE_API_TOKEN=$(cat /home/box/.secrets/cf_deploy_token) npx wrangler@4 deploy
```

## News (/news)

Single source of truth: `content/news.json` (metadata) + `content/news/<slug>.html` (post body, HTML fragment).
`news.html` and `news/*.html` are **generated** — do not edit them by hand.

**Pagination** — `/news` lists the 12 newest posts (sorted by `date`, then `updated`, newest first). Older posts go on `/news/page/2`, `/news/page/3`, … (12 per page, files `news/page/<n>.html`), with a Previous / numbered / Next `<nav aria-label="News pages">` under the list. Only page 1 has the intro and the "About this section" blocks; later pages get a "News — page N" heading, their own canonical, `index, follow` and a unique title. The build only writes pages that have posts, deletes stale page files when the count shrinks, and lists pages 2+ in `sitemap.xml`. With 12 or fewer posts there is no pagination nav and no `news/page/` folder. `_redirects` 301s `/news/page/1` to `/news` and trailing-slash/`.html` variants to the canonical URL; any page number without a file is a 404. `page` is a reserved slug. The page size is `PER_PAGE` in `scripts/build-news.mjs` (keep `scripts/check.mjs` in step).

**Add a post**
1. Write the body in `content/news/<slug>.html` (lowercase slug, hyphens). Start with a plain intro paragraph; use `<h2>` sections. Do not add the title, dates, sources or "More from News" — the build adds them.
2. Include a worked £ example run through the calculator logic in Node (`window.ProjectCostLab.calc(...)` after loading `js/data.js`, `js/projects-a.js`, `js/projects-b.js`, `js/app.js`) and state the inputs. End with an `<div class="update-box"><p><strong>Illustrative only.</strong> …</p></div>` disclaimer.
3. Add an entry to `content/news.json` → `posts`: `slug`, `title`, `description` (meta, ~155 chars), `date` and `updated` (YYYY-MM-DD), `category` (one of `categories`: Building costs, Grants & VAT, Planning, Energy), `readTime` (minutes; the build fails if it is >1 min off the body), `excerpt`, optional `updateDue` (renders the "Update due" box), and `sources` (`title` + https `url`, official sources only).
4. `node scripts/build-news.mjs && node scripts/check.mjs`, review, commit, push, deploy, then ping IndexNow for the new URL(s) — including any new `/news/page/<n>` the build created (it prints the page count).

**Update a post** — edit the body and/or JSON, set `updated` to today, remove or change `updateDue` once the awaited release is out, rebuild, check, commit, deploy. Corrections are made in place.

Rules: UK home-project costs only (not loans, borrowing, rates or credit); official sources (ONS, DBT, HMRC, HM Treasury, DESNZ, Ofgem, GOV.UK, MHCLG, Planning Portal; OBR only where relevant); never invent figures — if data is not out, write a preview with no predictions and an `updateDue` date; calm UK English; no advice to buy, borrow or commission work; no personal names (Rodway Labs only); no ads. If a guide is ever converted into a post, add a 301 for its old URL to the `extra` rules in `scripts/build-static-config.mjs`.

## Calculator notes (Nov 2026)

- The 8% "living in during works" uplift applies only to internal, structural and services jobs; `NO_OCCUPATION` in `js/data.js` lists the projects it skips (outside, roofing, garden, insulation, heating plant).
- Qualifying energy-saving installs (`ENERGY_SAVING`) default to 0% VAT until `ENERGY_VAT_ZERO_UNTIL` (31 Mar 2027), then 5%, unless the user changes VAT.
- Runs are shareable: inputs are written to the query string (`?p=&q=&s=&r=&a=&o=&l=&v=&c=&x=`) after the first edit and restored on load.
- Results link to Remortgage Lab's borrow-for-home-improvements calculator with the rounded mid (`?amount=`). No commission; disclosed on /advertising and /privacy.

## Indexing & ads

- `robots.txt` — `Allow: /` and `Sitemap: https://projectcostlab.co.uk/sitemap.xml`
- **Ad switch: `config/ads.json`.** With `enabled: false` (now) there is no ad code anywhere, `ads.txt` authorises no seller and the policy pages show their "no ads" wording (`<!-- ads-off -->` blocks).
- **To apply to AdSense:** add the site in AdSense to get the publisher ID → set `client` (`ca-pub-…`) and `enabled: true` → `node scripts/build.mjs && node scripts/check.mjs` → deploy → in AdSense, set up the **Privacy & messaging → European regulations** consent message (Google-certified CMP; needed for UK traffic) → request review. That build adds the account meta + loader to every page, writes `ads.txt`, switches the policy wording to the `<!-- ads-on … ads-on -->` blocks, adds the "Privacy and cookie settings" footer link and opens the CSP to Google's ad hosts. Test the live pages for CSP errors in the browser console after deploying.
- **After approval:** create display ad units and put their IDs in `slots` (`after-result`, `in-content`). Units only render in the reserved `<div class="ad-slot">` placeholders: below the calculator and mid-article on cost pages, never between the inputs and the result. Keep Auto ads off.
